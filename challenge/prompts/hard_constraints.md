# Hard constraints

- Begin from the immutable organizer FM seed. Every candidate must be AIDE-generated and self-contained; never import prior candidate code or load saved predictions, checkpoints, weights, or hidden-test artifacts.
- Optimize public-validation `GAUC`, `nDCG@5`, and `primary = (GAUC + nDCG@5) / 2`. A candidate wins the development gate only when it strictly exceeds `0.6710518008586268`, `0.5380142516919405`, and `0.6045330262752837`, respectively. A primary-only trade-off fails.
- Fit model state only from `train.csv`. Public-validation labels are evaluator feedback, never features, target encodings, history state, graph edges, or training examples.
- Serving-time validation columns are `user_id, video_id, date, hourmin, time_ms, duration_ms, tab`. Current-row engagement outcomes are unavailable. Training outcomes may be auxiliary targets or strictly earlier history only.
- A history event is eligible only when its timestamp is strictly earlier than the candidate. Emit features for every equal-user/equal-time group before updating state; never roll validation outcomes into later validation rows.
- The canonical internal chronological holdout is not a date-only mask. Compute `boundary_time_ms = min(time_ms where date >= 20220419)`, use `time_ms < boundary_time_ms` for the prefix and `time_ms >= boundary_time_ms` for holdout, and keep all equal timestamps in holdout. Assert the supplied-data values `boundary_time_ms == 1650295266482`, prefix rows `1079102`, and holdout rows `62010`. Fit vocabularies, bins, normalizers, target statistics, and graph structures on that prefix only. For the final public-validation model, rebuild preprocessing and fit only on all rows of `train.csv`; do not permanently map legal later-training categories to unknown or accidentally overweight the prefix by continuing a prefix fit without an explicit weighting plan. Never fit preprocessing on public validation. Pairwise negatives must be observed short-view impressions for the same user.
- `video_features_statistic_pure.csv` is forbidden. Preserve validation order and write exactly `./working/validation_predictions.csv` with `row_id,score`, row IDs `0..124908`, and finite scores.
- Read the seed from `AIDE_SEED` (default `0`) and use it for every source of randomness. Search acceptance is a single deterministic seed-0 execution; do not train or ensemble multiple random seeds.
- Candidate execution is offline and credential-free. Read only `./input`, write only `./working`, use at most four CPU threads, stay below 3 GB RAM, and finish within 900 seconds.
- Use the organizer evaluator if progress metrics are needed. The external deterministic evaluator remains authoritative.
- Make one bounded, attributable scientific change per node. For every `improve` or `refine` action, preserve the working parent backbone and localize the change; a wholesale rewrite is allowed only for a true draft with no valid parent. Use a zero-initialized or conservatively scaled residual/gate/blend when adding a risky mechanism, compare it with the parent on the same internal split, and state a parent-relative abort condition. Do not repeat a logged dead end unless the card identifies the new evidence and the exact material difference. Abandon or repair failures without changing the assigned hypothesis during repair.
- Cite literature only when the declared change actually implements that cited mechanism. For example, per-field gates are not FwFM field-pair weights. Treat experiment-memory metrics as evidence, never as permission to import prior code, predictions, or checkpoints.
- During a debug action, copy the scheduler's locked `model_family`, `scientific_change`, `hypothesis`, and `change_scope` values byte-for-byte into the new card. A repair may change implementation details only; rephrasing a locked field is a policy failure.
